## 目标

用 `@xyflow/react` 做出可用的工作流编辑器：拖拽添加节点、连线、配置面板、变量引用选择、运行态高亮、执行日志。

## 技术选型

| 项         | 选择                                  | 说明                                                                                         |
| ---------- | ------------------------------------- | -------------------------------------------------------------------------------------------- |
| 画布库     | `@xyflow/react` 12.11.x               | Dify 用的 `reactflow` v11 是同一项目的旧包名，v12 改名为 `@xyflow/react`。架构模式完全可迁移 |
| 状态       | zustand slice + React Flow 内部 store | 节点坐标/选中态由 React Flow 管，业务态（配置、运行状态、面板开合）走 zustand                |
| 表单       | react-hook-form + zod resolver        | 节点配置面板复用 contracts 的 schema 做校验                                                  |
| 代码编辑器 | CodeMirror 6                          | code 节点与提示词编辑用。比 Monaco 轻得多，Monaco 打包体积对桌面端不友好                     |

## 核心设计：单 CustomNode + 注册表分发

**这是最重要的一条，做错了后面全是返工。**

```tsx
// ✅ 正确：只注册一个，内部查表分发
const nodeTypes = { 'custom-node': CustomNode };

function CustomNode(props: NodeProps<WorkflowNodeData>) {
  const Body = NodeComponentMap[props.data.type];
  return (
    <BaseNode {...props}>   {/* 统一的边框、标题、连接桩、状态高亮 */}
      <Body data={props.data} />
    </BaseNode>
  );
}

// ❌ 错误：每种节点注册一个 nodeType
const nodeTypes = { start: StartNode, llm: LLMNode, ifElse: IfElseNode, ... };
```

为什么：`nodeTypes` 对象必须是稳定引用（否则 React Flow 会警告并重建全部节点）。节点种类多了以后，第二种写法会让"统一改所有节点的外观/状态高亮/右键菜单"变成到处改。第一种写法这些公共行为都在 `BaseNode` 里一处搞定。

## 三层注册表（与后端对称）

| 文件                          | 内容                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------- |
| `nodes/registry.ts`           | `NodeComponentMap`（画布上的方块）、`PanelComponentMap`（右侧配置面板）             |
| `nodes/<type>/default.ts`     | `metaData`（名称、图标、分类、排序）、`defaultValue`、`checkValid`、`getOutputVars` |
| `block-selector/constants.ts` | 按分类组织的可添加节点清单                                                          |

`getOutputVars` 是变量选择器的数据来源：它声明这个节点会产出哪些变量、什么类型。下游节点的变量选择器读所有上游节点的 `getOutputVars` 来生成候选列表。

## 变量选择器（体验关键点）

节点配置里引用上游变量时，不能让用户手打 `{{#node_abc.text#}}`——节点 id 是随机生成的，没人记得住。

要做一个级联选择器：

```
┌─────────────────────────────┐
│ 选择变量                     │
├─────────────────────────────┤
│ ▸ 开始 (start)              │
│     query        String     │
│ ▸ 知识检索 (node_a1b2)      │
│     chunks       Array      │
│ ▸ LLM (node_c3d4)          │
│     text         String     │
│ ▸ 系统变量                   │
│     sys.query    String     │
└─────────────────────────────┘
```

实现要点：

1. 候选来源 = 当前节点在拓扑序中的**所有上游节点**的 `getOutputVars()`。不是所有节点——引用下游节点是逻辑错误，选择器里就不该出现。
2. 显示用节点标题，存储用 `ValueSelector`（`[nodeId, field]`）。
3. 节点被删除后，引用它的变量要标记为失效（红色提示），不能静默变成空值。
4. 提示词模板里支持内联插入变量，用 `{{#...#}}` 语法，编辑器里高亮显示。

## 运行态展示

```
点击「运行」
  → 弹出入参表单（根据 start 节点定义的字段生成）
  → 建立 SSE 连接
  → 事件驱动更新画布与日志面板
```

| 事件                | 画布反应                | 日志面板反应                               |
| ------------------- | ----------------------- | ------------------------------------------ |
| `workflow_started`  | 清除上次状态            | 新建运行记录                               |
| `node_started`      | 节点边框变蓝 + 呼吸动画 | 追加节点条目，状态「运行中」               |
| `node_stream_chunk` | —                       | LLM 节点条目里逐字显示输出                 |
| `node_finished`     | 边框变绿                | 状态「成功」，展开可看 inputs/outputs/耗时 |
| `node_failed`       | 边框变红                | 状态「失败」，显示错误信息                 |
| `workflow_finished` | 全部恢复常态            | 汇总耗时与 token 用量                      |

运行态字段（`_runningStatus` 等）写在 `node.data` 上但**不进持久化**。保存图时要过滤掉下划线前缀字段——这个过滤要在一处统一做（保存前的序列化函数里），不要指望每个地方都记得。

## 性能

节点多了以后画布容易卡。四条措施：

1. **节点组件 memo**，且 props 里不传对象字面量（否则 memo 失效）。
2. **配置面板与画布解耦**：面板里输入文字不应该触发画布重渲染。做法是面板的表单状态先本地持有，失焦或防抖后才写入 store。
3. **拖拽时不同步草稿**：拖动节点会高频触发坐标变化，草稿自动保存要防抖（1 秒以上）。
4. **日志面板虚拟化**：一次运行的日志条目可能上百条，配合流式输出会很卡。

## 实施步骤

1. 空白画布跑通：`@xyflow/react` 挂载、`Background`、`Controls`、`MiniMap`、缩放平移。
2. zustand store 骨架：nodes、edges、selectedNodeId、panel 状态、运行态。
3. `BaseNode` + `CustomNode` + 注册表机制，先用一个占位节点验证分发能跑。
4. 节点面板（左侧）+ 拖拽添加 + 从注册表读分类。
5. 连线规则：start 无入边、end 无出边、禁止自环、禁止重复边、类型兼容校验。
6. 前四个简单节点的 node/panel/default：`start`、`end`、`variable-assigner`、`if-else`。
7. 变量选择器组件（上游节点收集、级联选择、失效检测）。
8. 剩余四个节点：`llm`、`knowledge-retrieval`、`code`、`http-request`。
9. 图的保存与加载：草稿自动保存（防抖）、运行态字段过滤、版本号。
10. 前端图校验：调用后端 `/validate`，把错误定位到具体节点并高亮。
11. 运行入参表单（根据 start 节点配置动态生成）。
12. SSE 运行态：画布高亮 + 日志面板。
13. 单节点调试面板。
14. 性能优化四条措施。
15. 键盘快捷键：删除、复制粘贴、撤销重做（撤销重做用 zustand 中间件或简单的状态快照栈）。

## 风险与备选

| 风险                                              | 处置                                                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `@xyflow/react` v12 与 Dify 参考的 v11 API 有差异 | v12 主要变化是包名、`useNodesState` 的类型泛型、部分 props 重命名。遇到不一致以 v12 官方文档为准，不要照抄 Dify 的 v11 代码                 |
| 配置面板表单与画布 store 双向同步导致循环更新     | 单向数据流：面板改动 → dispatch 到 store → store 更新 → 面板从 store 读初值（但不受控地跟随）。用 `key={nodeId}` 强制面板在切换节点时重挂载 |
| 撤销重做实现复杂                                  | 第一版用简单的状态快照栈（保存整个 nodes+edges 数组的深拷贝），限制栈深度 20。图不大时内存完全够用。不要一开始就上 immer patch 或 CRDT      |
| 节点数量多时画布卡顿                              | 按性能四条措施排查。React Flow 有 `onlyRenderVisibleElements` 选项可开                                                                      |
| 变量选择器的上游节点收集在有环图上死循环          | 收集函数必须带 visited 集合。图校验应该在此之前就拦住环，但收集函数自己也要防御                                                             |
| CodeMirror 6 的配置比预期复杂                     | 只需要基础能力（语法高亮、行号、自动缩进）。不要引入 lint、自动补全、多光标这些，用不上还增加体积                                           |
