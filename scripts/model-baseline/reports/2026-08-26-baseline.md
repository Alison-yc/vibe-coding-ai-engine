## 因此本项目决定

数据出处均为上表；能力值写入 `OllamaLlmGateway.capabilities()`，来源字段为本报告路径。

1. **Agent 走标准 function calling（ADR-D01 路线 A）**。`qwen3.5:2b` 在 1/3/6/12 个工具下合法 JSON 率与选择正确率均为 1.0，3 工具假阳性为 0，嵌套参数与两步编排均为 1.0。12 工具时参数正确率降到 0.95。
2. **`maxToolCount = 6`**。6 工具仍全指标 1.0；12 工具虽可工作，但参数正确率开始下滑。Agent 默认装配不超过 6 个工具。
3. **`needsToolCallFallback = false`（仅 qwen3.5:2b）**。合法 JSON 率全程 1.0，不需要结构化输出降级路径。业务层仍用 zod 校验参数。
4. **结构化输出必须用 Ollama JSON Schema / `format`，禁止纯提示词要 JSON**。json-mode 与 few-shot 的 validRate 均为 1.0；prompt-only 全程 0（模型包 markdown 代码块）。
5. **默认 `numCtx = 8192`**。8192 目标长度下实际 prompt token 约 4337，三位置召回 1.0，热延迟约 3.4s。32768 窗口下实际 17240 token 仍 100% 召回，但延迟约 14s，不做默认。`effectiveContextTokens = 8192`，与默认 `numCtx` 对齐，供 RAG 截断。
6. **默认 `numPredict = 2048`**。本轮 latency 表未单独测输出截断拐点；旧值 128 会截断半句话（plan 04 定性），故采用 `.env.example` 的 2048 作为上限。
7. **超时**：embed 30s；非流式 chat 120s（覆盖冷启动 5.4s）；流式**首 token** 30s（覆盖冷启动首 token 3.0s 的约 10 倍余量）。只对连接错误重试，上限 2 次。
8. **Embedding 默认按语义边界切分**。`semantic-boundary` 的 MRR 最高（0.924），`paragraph` 的 Recall@3 最高（0.96），均优于 `fixed-512`。维度确认为 768。
9. **`gemma4:e2b` 不做默认模型**。冷启动首 token 3.8s；本轮未测其 tool call，`supportsTools = false`。
10. **工作流 if-else 仍用代码判断**。json-mode 虽可用，但同一输入两次运行不能走不同分支；语义判断放在独立 LLM 节点，条件节点只读其结构化结果。
